1. Research Question

The platform is built around a simple question: Does the same AI system behave consistently when the language, dialect, script, provider, model version, or time changes? VIHAA LINGUA-360 turns that question into repeatable experiments rather than relying on a single headline accuracy number.

The platform does not claim that one evaluator score proves factual accuracy, fairness, or safety. Cross-language consistency and factual correctness are related but different questions.

2. Core Evaluation Pipeline

Each experiment records the language, provider, model identifier, timestamp, latency, provider-reported token usage where available, response, optional judge output, and provider error state.

3. Reproducibility

Each benchmark run receives a unique Run ID. Local history can be used to compare the same model-language combination over time. Share snapshots exclude API keys and raw credentials. Model identifiers and timestamps are preserved so later runs can be compared to earlier runs.

Recommended protocol

  • Fix prompt set and language set.
  • Record exact model IDs and provider endpoints.
  • Keep temperature constant when supported.
  • Repeat runs to estimate variability.
  • Publish failures alongside successes.

5. Dialect Intelligence

The Dialect Intelligence Lab rewrites a prompt into regional or register variants and sends each rewritten prompt to a real answer model. The platform can optionally compare those answers using a configured judge. Current families include Telugu, Arabic, Spanish, English, and Hindi variants.

Dialect outputs are generated by models and can contain imperfect regional phrasing. Native-speaker review is the preferred validation layer.

6. Refusal & Disagreement

The refusal monitor classifies response behavior across languages, while the disagreement detector compares two real model answers for the same language. These views are intended to reveal behavior differences, not to declare a model correct or incorrect without external evidence.

7. Explore Mode

Explore Mode turns the research platform into a user-facing multilingual knowledge assistant. Users can select a language and answer depth, ask a question through a connected provider, receive a structured response, listen through browser speech synthesis, download a designed PDF, or send the same question into Benchmark Mode.

8. Voice Layer

The Voice Benchmark uses browser/device speech recognition and speech synthesis when available. It does not invent speech-recognition or pronunciation accuracy scores. Browser, operating-system, language-pack, and device support can affect availability.

9. Benchmark Packs

Versioned prompt packs provide repeatable starting points for Healthcare Safety, Cybersecurity, Education, Emergency Safety, Banking & Scam Safety, AI Ethics, and General Knowledge. The public JSON manifest includes prompts but no fabricated model results.

Public manifest: /benchmark-packs.json

10. Privacy & Credential Handling

  • API keys are entered client-side and are not included in exported share snapshots.
  • Local run history is stored in the browser only.
  • Public production deployment should move provider credentials behind a secure server-side proxy.
  • Users should avoid placing organization-wide master keys into a public browser client.

11. Known Limitations

  • AI judges can be biased, inconsistent, or language-sensitive.
  • Translation can introduce error before answer generation.
  • Current map markers approximate language geographies, not national populations.
  • Static deployment cannot provide a shared public leaderboard database by itself.
  • Explore Mode is not a substitute for authoritative high-stakes sources.

12. Suggested Research Use

For a publishable study, pre-register the prompt set, select exact model versions, use repeated trials, document evaluator prompts, include native-speaker review for target languages, report confidence intervals where appropriate, preserve failures, and separate consistency metrics from source-grounded factual verification.
